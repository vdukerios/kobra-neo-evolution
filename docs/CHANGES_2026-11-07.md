# Changes of 7 November 2026

First hardware tests of the audited source on the author's Kobra Neo (one printer, Keil MDK 5 / Arm Compiler 5). Everything below was found by running the firmware, fixed in the source and re-built. **A single printer has been used; treat this as early feedback, not a validation.**

## Found and fixed during the tests

| Problem seen on the printer | Cause | Fix |
|---|---|---|
| Home screen flickered when turning the wheel | Every turn asked for a full "clear and redraw" | Turning the wheel now repaints without clearing |
| Part cooling fan stayed **off** during a print (`Error:Invalid fan value`) | The audit's input check rejected fan speeds with decimals, such as the `M106 S127.5` Cura writes | `P` and `I` stay integers; `S` and `T` accept decimals |
| Express mode never took effect; the thumbnail and the estimated time vanished when a print started | Leaving the "Confirm print" screen was treated as a cancel, because the file is opened through the command queue and was not open yet | A "starting" flag keeps mode, thumbnail and estimate until the job ends or is aborted |
| Cancelling during a long wait (`G4 S420`) did nothing until the wait ended, and the screen stayed on "Print aborted" | The abort request is only handled in the main loop, which a dwell never returns to | The dwell now ends when an SD print is aborted |
| Cancelling a USB print left the screen "printing" | The job timer was not stopped for host prints | The timer is stopped on abort |
| "Level and center" left the nozzle at Z = 0.5, so the saved Z offset included that 0.5 mm (about -0.9 instead of -0.34) | The final Z was 0.5 mm and the Z-offset editor stores the whole travel | The stop height is now Z = 0 (standard paper method); the nozzle heats to 200 C before lowering |
| No remaining time on the print screen | Cura writes only a total (`;TIME:`) and no `M73` | The firmware reads `;TIME:` when the file is picked, corrects it with the learned factor and spreads it with the file progress. With `M73` lines (script `AgregarM73`) those are used instead |
| Remaining time jumped from 1:30 to 2 h | An extrapolation counted heating and the initial wait | Removed (see above) |

## Print modes

- **Express** now also skips any fixed wait of **30 s or longer** (`G4`) when printing from the SD card, so it works with any G-code and does not depend on the `M1100` command. Heating waits (`M190`, `M109`) are never skipped. Shorter waits are kept.
- Full mode, `M1100` and the rest are unchanged.

## Cura

- New one-command installer [`cura/install_cura.py`](../cura/install_cura.py) (`install_cura.bat` on Windows): copies and enables the two scripts, writes start/end G-code and machine limits, optionally installs the profiles. Backs up everything it touches and can undo (`--uninstall`). See [`CURA_SETUP.md`](CURA_SETUP.md).
- New profile **PLA Rapido** (fast PLA), see [`../cura/profiles/README.md`](../cura/profiles/README.md). Not measured: the real maximum flow of the hotend.
- `--classic-start` writes a start G-code with explicit steps (bed and nozzle heat together, 2 minute soak, home, saved mesh) instead of `M1100`.

## Things to know

- **Eject the SD card from the computer before removing it.** A card removed while it was being written ended up with a corrupted file table and had to be formatted.
- Copy `firmware.bin` and **flush the volume** (on Windows, eject the card) before putting it in the printer. A bad copy shows as a boot loop (black screen, restart).
- Open items: the estimated time line on the "Confirm print" screen made the firmware fail to boot in two attempts and was left out; its cause is unknown. Other numeric checks added by the audit may also reject legitimate G-code (`M201`, `M205 B`); they have not been exercised with real slicer output.
