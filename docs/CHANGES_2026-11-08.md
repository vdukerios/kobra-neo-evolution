# Changes of 7-8 November 2026 (after the first hardware tests)

Built with Keil MDK 5 / Arm Compiler 5 and **not yet validated on a printer**: these changes compile and the simulator checks pass, but they have not been run on the author's Kobra Neo. Earlier fixes are in [`CHANGES_2026-11-07.md`](CHANGES_2026-11-07.md).

## New

| Change | Notes |
|---|---|
| **Light / dark theme** | "Light theme" switch next to "Night mode" (main menu, also while printing). Applies at once and is remembered across power-offs (stored in bit 7 of the language byte in the EEPROM; the settings layout does not change and old settings load as dark). It is not saved while printing. The light palette has not been looked at on the real display yet. |
| **Complete mode measures the bed by itself** | After the first `G28` of an SD job the firmware runs `G29` (hot mesh), checks it, and restores the bed and nozzle temperatures the G-code had asked for. Once per job; not in Express, not if the G-code uses `M1100`. If the mesh fails the heaters are switched off and the job is aborted. The saved mesh is **replaced** on every Complete print. |
| **Z offset without homing** | The Z-offset editor ignored the wheel when the axes were not homed. It now changes the stored value (applied at the next `G28`); with homed axes it still adjusts live. |

## Fixed

| Problem | Cause | Fix |
|---|---|---|
| Remaining time jumped (12 min became 9 min when the heaters switched on) and Complete mode added no preparation time | Progress was measured by bytes read, which counted the header, thumbnail and start G-code (23 % of a small file) and made the firmware think the preparation was over | Progress now starts at the `;LAYER:0` line that Cura writes after the start G-code; the preparation ends when the file passes it |
| Progress and time ignored heating and levelling | The job timer starts at the first heating command but the progress stayed at 0 % | During preparation the remaining time is the estimated preparation plus the part time; progress is elapsed / (elapsed + remaining). The preparation estimate is a fixed guess: 3 min (Express) and 10 min (Complete) |
| The learned time factor mixed in the preparation and never learned without `M1100` and `M73` | Learning needed both | The firmware detects the end of the preparation itself, subtracts it (Express and Complete become comparable) and uses the Cura `;TIME:` header when there is no `M73` |

## Open items

- The estimated-time line on the "Confirm print" screen made the firmware fail to boot in two attempts and is not included; the cause is unknown.
- The fixed 3 / 10 minute preparation guesses should be replaced by measured values per mode.
- Numeric checks added by the audit may still reject legitimate G-code (`M201`, `M205 B`).
- Simulator: regenerated from this source (88 cases pass). It does not show the new "Light theme" switch's colours.
